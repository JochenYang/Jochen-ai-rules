## 阶段 3: 用户故事编写

### 用户故事格式
```
作为 [用户角色]
我想要 [功能]
以便 [业务价值]
```

### 验收标准
- [ ] 定义明确的验收条件
- [ ] 使用 Given-When-Then 格式
- [ ] 覆盖正常和异常场景
- [ ] 可测试和可验证

### 示例
```
用户故事：用户登录

作为一个注册用户
我想要登录系统
以便访问我的个人数据

验收标准：
- Given 用户已注册
- When 输入正确的邮箱和密码
- Then 成功登录并跳转到首页

- Given 用户输入错误密码
- When 点击登录
- Then 显示错误提示"邮箱或密码错误"
```

## 常用分析方法

### SWOT 分析
- **Strengths** - 优势
- **Weaknesses** - 劣势
- **Opportunities** - 机会
- **Threats** - 威胁

### 5W2H 分析
- **What** - 做什么
- **Why** - 为什么做
- **Who** - 谁来做
- **When** - 什么时候做
- **Where** - 在哪里做
- **How** - 怎么做
- **How much** - 成本多少

### KANO 模型
- **基本型需求** - 必须满足
- **期望型需求** - 满足度与满意度成正比
- **兴奋型需求** - 超出预期的惊喜
- **无差异需求** - 可有可无
- **反向需求** - 不应该有

## 输出格式

### PRD 文档结构

```markdown
# 产品需求文档（PRD）

## 1. 产品概述
- 产品背景
- 目标用户
- 核心价值
- 成功指标

## 2. 功能需求
### 2.1 用户认证
- 用户注册
- 用户登录
- 密码重置

### 2.2 用户管理
- 个人资料编辑
- 头像上传
- 账号设置

## 3. 非功能需求
- 性能：API 响应时间 < 200ms
- 安全：HTTPS、JWT 认证
- 可用性：99.9% 可用性

## 4. 技术约束
- 前端：React + TypeScript
- 后端：Node.js + PostgreSQL
- 部署：Vercel + Railway

## 5. 里程碑
- Week 1-2: 用户认证
- Week 3-4: 用户管理
- Week 5: 测试和优化
- Week 6: 发布
```
