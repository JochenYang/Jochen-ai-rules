# PRD 模板

## 产品需求文档（Product Requirements Document）

---

## 1. 产品概述

### 1.1 产品背景
- **问题陈述**：描述要解决的问题
- **目标用户**：谁会使用这个产品
- **市场机会**：为什么现在做这个产品
- **竞品分析**：现有解决方案的优劣

### 1.2 产品目标
- **业务目标**：提升什么业务指标
- **用户目标**：帮助用户实现什么
- **成功指标**：如何衡量成功（KPI）

### 1.3 核心价值主张
用一句话描述产品的核心价值：
> 对于 [目标用户]，他们想要 [用户需求]，我们的产品 [产品名称] 是一个 [产品类别]，它能够 [核心能力]。不同于 [竞品]，我们的产品 [差异化优势]。

---

## 2. 用户画像

### 2.1 主要用户群体
**用户 A：[用户类型]**
- **人口统计**：年龄、职业、收入
- **行为特征**：使用习惯、技术水平
- **痛点**：遇到的主要问题
- **目标**：想要达成的目标
- **使用场景**：在什么情况下使用

**用户 B：[用户类型]**
- （同上）

### 2.2 用户旅程
1. **发现阶段**：用户如何发现产品
2. **注册阶段**：用户如何开始使用
3. **使用阶段**：用户如何完成核心任务
4. **留存阶段**：用户为什么持续使用

## 3. 功能需求

### 3.1 功能优先级（MoSCoW）

#### Must Have（必须有）
1. **用户认证**
   - 用户注册
   - 用户登录
   - 密码重置

2. **核心功能 A**
   - 功能描述
   - 用户故事
   - 验收标准

#### Should Have（应该有）
1. **功能 B**
   - 功能描述
   - 用户故事
   - 验收标准

#### Could Have（可以有）
1. **功能 C**
   - 功能描述
   - 用户故事
   - 验收标准

#### Won't Have（不会有）
1. **功能 D**
   - 为什么不做
   - 未来可能性

---

### 3.2 用户故事

**格式**：
```
作为 [用户角色]
我想要 [功能]
以便 [业务价值]

验收标准：
- Given [前置条件]
- When [操作]
- Then [预期结果]
```

**示例**：
```
作为一个新用户
我想要注册账号
以便使用产品功能

验收标准：
- Given 用户访问注册页面
- When 输入邮箱、密码并点击注册
- Then 创建账号并发送验证邮件

- Given 用户输入已存在的邮箱
- When 点击注册
- Then 显示错误提示"该邮箱已被注册"
```

## 4. 非功能需求

### 4.1 性能要求
- **响应时间**：API 响应时间 < 200ms
- **并发用户**：支持 1000 并发用户
- **数据量**：支持 100 万条数据
- **可用性**：99.9% 可用性

### 4.2 安全要求
- **认证**：JWT Token 认证
- **授权**：基于角色的访问控制（RBAC）
- **数据加密**：HTTPS 传输，敏感数据加密存储
- **审计**：记录关键操作日志

### 4.3 可用性要求
- **易用性**：新用户 5 分钟内完成核心任务
- **可访问性**：符合 WCAG 2.1 AA 标准
- **多语言**：支持中文、英文
- **响应式**：支持移动端、平板、桌面

### 4.4 兼容性要求
- **浏览器**：Chrome、Firefox、Safari、Edge（最新两个版本）
- **移动端**：iOS 14+、Android 10+
- **屏幕尺寸**：375px - 1920px

---

## 5. 技术约束

### 5.1 技术栈
- **前端**：React 18 + TypeScript + Tailwind CSS
- **后端**：Node.js + Express + PostgreSQL
- **部署**：Vercel（前端）+ Railway（后端）
- **第三方服务**：Auth0（认证）、Stripe（支付）

### 5.2 技术限制
- 必须使用现有技术栈
- 必须兼容现有系统
- 必须符合公司安全标准

### 5.3 第三方依赖
- **认证服务**：Auth0
- **支付服务**：Stripe
- **邮件服务**：SendGrid
- **存储服务**：AWS S3

## 7. 数据模型

### 7.1 核心实体

**User（用户）**
```
- id: UUID
- email: String (unique)
- password: String (hashed)
- name: String
- avatar: String (URL)
- createdAt: DateTime
- updatedAt: DateTime
```

**Post（文章）**
```
- id: UUID
- userId: UUID (foreign key)
- title: String
- content: Text
- status: Enum (draft, published)
- createdAt: DateTime
- updatedAt: DateTime
```

### 7.2 关系
- User 1:N Post（一个用户有多篇文章）
- Post N:1 User（一篇文章属于一个用户）

---

## 8. API 设计

### 8.1 RESTful API

**用户认证**
```
POST /api/auth/register - 用户注册
POST /api/auth/login - 用户登录
POST /api/auth/logout - 用户登出
POST /api/auth/reset-password - 密码重置
```

**用户管理**
```
GET /api/users/:id - 获取用户信息
PUT /api/users/:id - 更新用户信息
DELETE /api/users/:id - 删除用户
```

**文章管理**
```
GET /api/posts - 获取文章列表
GET /api/posts/:id - 获取文章详情
POST /api/posts - 创建文章
PUT /api/posts/:id - 更新文章
DELETE /api/posts/:id - 删除文章
```

### 8.2 API 规范
- 参考 `../../api-designer/SKILL.md` 和 `../../developer/guides/api-design.md`

## 9. 测试策略

### 9.1 测试类型
- **单元测试**：覆盖率 > 80%
- **集成测试**：覆盖关键业务流程
- **E2E 测试**：覆盖核心用户路径
- **性能测试**：验证性能指标

### 9.2 测试工具
- **单元测试**：Vitest
- **E2E 测试**：Playwright
- **API 测试**：Supertest

## 10. 里程碑和时间线

### 10.1 开发阶段

**Phase 1: MVP（4 周）**
- Week 1-2: 用户认证
- Week 3-4: 核心功能 A

**Phase 2: 功能完善（4 周）**
- Week 5-6: 功能 B
- Week 7-8: 功能 C

**Phase 3: 优化和发布（2 周）**
- Week 9: 性能优化、安全加固
- Week 10: 测试、修复 Bug、发布

### 10.2 关键里程碑
- **Week 2**：用户认证完成
- **Week 4**：MVP 完成
- **Week 8**：功能完善
- **Week 10**：正式发布
